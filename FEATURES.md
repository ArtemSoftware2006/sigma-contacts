# Sigma-Contacts — Features & Roadmap

## Реализовано

### Авторизация
- [x] Регистрация (nickname + password с валидацией)
- [x] Вход → JWT-токен (HS256, 1024ч)
- [x] Защищённые маршруты через middleware
- [x] Ролевой доступ: `user` / `admin`

### Пользователи
- [x] Получить текущего пользователя (`GET /users/me`)
- [x] Создать пользователя
- [x] Обновить профиль (имя, фамилия, nickname)
- [x] Получить всех пользователей (только admin)

### Граф
- [x] Создать граф пользователя — автоматически появляются 6 дефолтных групп: Коллеги, Родственники, Школа, Соседи, Университет, Знакомые
- [x] Получить граф по ID
- [x] Получить граф текущего пользователя
- [x] Проверка владельца графа

### Узлы (Nodes)
- [x] Добавить контактный узел (с привязкой к группе через `parentId`)
- [x] Добавить группу-узел (`isGroup=true`)
- [x] Обновить узел (label, позиция X/Y, цвет, размер)
- [x] Удалить узел
- [x] Каскадное распространение цвета группы на дочерние узлы (`PropagateGroupColor`)

### Контакты
- [x] Добавить контакт (имя, фамилия, телефон, VK, Telegram, WhatsApp, GitHub, комментарий)
- [x] Обновить контакт
- [x] Удалить контакт

### Аналитика
- [x] Базовая статистика графа (`GET /analytics/baseInfo`)

### Валидаторы
- [x] Пароль: минимум 9 символов, заглавные + строчные + 2 спецсимвола
- [x] Логин: максимум 15 символов
- [x] Email-валидатор
- [x] Телефон-валидатор

### Фронтенд
- [x] Страница входа / регистрации
- [x] Визуализация графа через Sigma.js + Graphology
- [x] Перетаскивание узлов мышью
- [x] Контекстное меню по правому клику на узле
- [x] Панель настроек (CRUD узлов и контактов)
- [x] Страница профиля
- [x] Таблица пользователей для администратора
- [x] Карточки статистики графа
- [x] PrivateRoute — редирект на /login без токена

### Инфраструктура
- [x] Docker Compose: backend + MongoDB + mongo-express + frontend
- [x] Multi-stage Dockerfile для backend (Go Alpine)
- [x] Структурированное логирование (logrus): текст в dev, JSON в prod
- [x] CORS: все origins, методы GET/POST/PUT/DELETE

## Идеи для улучшения

### Высокий приоритет

**1. Категории узлов**
Выпадающий список при создании контакта: коллега / родственник / школа / сосед / знакомый / искусство / университет.
Хранится в поле `category` на узле. Используется для фильтрации и цветовой маркировки.

> **Рассмотреть:**
> - Управление категориями пользователем — добавление / переименование / удаление своих категорий (сейчас список жёстко задан в коде)
> - Обязательность категории при создании контактного узла — не давать добавить контакт без выбранной категории
> - Автовыбор категории при добавлении узла: если пользователь открыл форму через клик на узел-группу, подставлять категорию, совпадающую с именем группы (например, клик на «Коллеги» → категория «Коллеги» выбрана автоматически)

**2. Типы и веса связей (рёбра)**
Сейчас рёбра — просто линии с цветом. Добавить:
- Тип: дружба / работа / родство / знакомство
- Сила связи: число 1–5 (влияет на толщину линии)
- Дата начала знакомства

**3. Фильтрация на графе**
Панель фильтров: показать только узлы категории X, только группу Y, только с тегом Z.
Sigma.js поддерживает скрытие узлов — не нужна перезагрузка данных.

**4. Поиск по контактам**
Строка поиска → highlight узла на графе. Поиск по имени, nickname, телефону.

---

### Средний приоритет

**5. Теги на узлах**
Свободные теги (`[]string`) на каждом контакте. Фильтрация по тегу.
Пример: `#Python`, `#спорт`, `#школа2015`.

**6. Заметки к связям**
Поле `comment` на ребре: как познакомились, общие интересы, контекст.

**7. Временная шкала знакомства**
Поле `metAt time.Time` на узле. Сортировка контактов по дате знакомства.
Фильтр: показать всех, с кем познакомился в 2020–2022.

**8. Напоминания**
Дни рождения контактов. Уведомление в UI (toast) или email.

**9. Фото контакта**
Поле `avatarUrl string`. Хранить в S3 / локальной папке.
Аватар отображается в узле на графе.

**10. Экспорт / импорт**
- Экспорт: JSON, CSV
- Импорт: CSV с контактами
- Резервная копия всего графа

### Технический долг

**11. Refresh-токены**
Сейчас access-токен живёт 1024ч. Нужны: short-lived access (15мин) + refresh (30 дней).

**12. `children[]` не заполняется**
Поле `Children []string` в Node entity объявлено, но никогда не записывается.
Нужно: при добавлении дочернего узла пушить его ID в `children` родителя.

**13. Передавать context в репозитории**
Сейчас `context.WithTimeout` создаётся внутри каждого репозитория.
Правильно: принимать `context.Context` первым аргументом из контроллера.

**14. Регистрация должна возвращать токен**
Сейчас: register → 201 без токена → клиент вручную делает login.
Нужно: register сразу возвращает `{token, user}` как login.

**15. Несколько графов на пользователя**
Сейчас: 1 пользователь = 1 граф. Добавить поддержку нескольких графов:
работа / личное / проект.

### Долгосрочно

**16. Поиск пути между контактами**
«Через кого я знаком с Иваном?» — BFS/Dijkstra по графу.

**17. Кластеризация**
Автоматически предлагать группы на основе связей (community detection).

**18. PWA / мобильная версия**
Добавить service worker, адаптивную вёрстку для телефона.

**19. Коллаборативные графы**
Поделиться графом с другим пользователем (read-only или edit).
